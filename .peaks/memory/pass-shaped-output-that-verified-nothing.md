# 长得像通过、其实什么都没验

2026-10-09 同一次 24h 运行里，**三次**遇到同一类失真：**退出码 0 / 绿色输出，但零验证**。三次形态不同，检测手段相同。

## 三例

| # | 形态 | 表现 |
|---|---|---|
| 1 | **`skipIf` 守着整套证明** | 移开构建产物 → `1 skipped / 9 skipped`，**exit 0**。三层只读证明凭空消失。见 [[proof-gated-by-skipif-can-vanish-and-report-success]] |
| 2 | **自失效 fixture** | 集成测试断言 `rid-036` 不存在，而那个工件正是该子代理自己的报告 → 它**只能在自己所支撑的证据尚未存在时通过**。见 [[subagent-evidence-must-hold-at-delivery-state]] |
| 3 | **无参跑门** | `node .husky/peaks-gate.mjs staged` **不带文件参数**时打印 `EMPTY CHANGE SET — 0 in-scope files, NOTHING WAS CHECKED` 并 **exit 0**。门自己的注释里警告过这件事 |
| 4 | **两个检查范围不一致**（2026-10-09 实测） | `pnpm format:check` 覆盖 `tests/**` + `scripts/**`；**pre-commit 门不覆盖**（它把这两个目录列为 "outside the lint scope, **not compared**"）。于是**提交时门绿、而 `format:check` 红**——我们自己的提交引入了 9 个未格式化文件，一路放行。**CI 也不跑 `format:check`**，所以没有任何环节会红 |

第 3 例尤其值得记：它**是门自己**犯的，且文档里已写明危险。**"我不知道要传文件列表"就会得到一个漂亮的红利。**

## 共同的检测问题

> **面对一个绿色的检查，问的不是"它绿了吗"，而是"它绿的时候，究竟验了什么？"**

具体成三个可执行动作：

1. **要求"它红过"**：证明/守卫类断言必须在**注入违规**后转红。不红的一层＝不存在。（本运行中三层证明的 A/B/C 与守卫都做了注入控制，全部 LIVE——**这一步救了整个 slice ①**。）
2. **要求"交付态可复现"**：在**最终交付的那一刻**重跑。若某结果依赖"某物尚不存在"，它不是结果。
3. **要求计数能对上**：看到 `N passed` 就核对 N 与交付态是否一致；对不上则整份报告的证据可信度下调。**优先核那些"太好看"或"太方便"的结论**（"全绿"、"失败都是既有的"、"跑一下就过了"）。

## 为什么这类失真比崩溃危险

崩溃有声音，失真没有。它会以"已验证"的姿态进入交付记录、进入后续切片的前提、进入人类审阅者的信任。本次三例中：

- 第 2 例若未被对抗性 QA 抓到，会写进交付记录的是一个**不可复现的绿**；
- 第 3 例若未被一个恰好较真的子代理发现，**后续每一次提交都会带着"我跑过门了"的错觉**。

## How to apply

- 设计任何**证明装置**时：入口守卫**不得用 skip**；缺前提＝红。
- 写任何**断言"某物不存在"**的测试时：fixture 用**结构性不可能**的值，不要用会真实存在的 id。
- 跑任何**门/守卫**时：确认它**收到了被检对象**；无参运行=零验证。
- 审查他人（或子代理）的"通过"时：先看**它验了什么**，再看它是绿是红。
