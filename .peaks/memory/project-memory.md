**现象**：本 session 的每一片都出过"测试全绿却存在真缺陷"的情况，形状完全一致 ——
作者挑的 fixture 里不含能打破它的那个输入。

**具体实例**：S1 的六类假 EXACT（未变字段被报成变更）、相对路径在 `--project` 不同
时拼成双份、S4 的 hook 扫描被关在 legacy-only 门禁后在 greenfield 上完全失效、
箭头函数式 hook 被取到嵌套块当函数体从而把真 hook 标成离群、一行注释就能改写整个
项目的"主导约定"。

**Why 危险**：绿测试只证明"它在作者想得到的输入上对"。而这五条没有一条是测试能发现
的 —— 它们全部由编排器**亲自跑真实命令**发现。

**How to apply**：
- 测试必须断言**缺席**，不能只断言存在（"未变的字段不应产生任何行"）。
- 任何检测器的第一问是"**读不全时它说什么**"。正确设计是**两侧都证明完整才敢断言，
  否则压制并说明原因**；单侧 fail-safe 是不对称的，迟早暴露。
- 行式/正则解析 TS 的边界是无界的：把"不可分类"默认成"不完整"，而不是默认成"没有"。
