# peaks-loop 4.0.10 publish closure (2026-08-04)

## 触发场景

**用户原始反馈**："现在在 4.0.9 状态下，statusline 永远显示 `peaks empty`" + 追问"我开发另外的项目效果好很多，当前是 monorepo+pg 数据库..." + 误以为是 `prototype_v5.html` HTML 原型问题。

**真实根因**：`peaks-loop@4.0.9` 在 Windows Git Bash 下，binding 写入时是 `C:\Users\...`（反斜杠），CLI 传 `C:/Users/...`（正斜杠），`readSessionFile` 用 `data.projectRoot === projectRoot` 严格相等 → 返回 null → 4.0.8 fail-closed `PEAKS_SESSION_NOT_BOUND` 拦截 `peaks skill presence:set` → statusline 永远 inactive → 渲染 `peaks empty`。

**WHY**: 这个 bug 静默，不抛错，只在 Windows Git Bash 复现。macOS/Linux 用户看不到——4.0.9 发布当天 Windows 用户全网 0 反馈，因为没装到 Windows 上的项目就看不到。

**HOW TO APPLY**: 任何未来 peaks-loop session 涉及 path 比较 / statusline 配置 / `peaks skill presence:set` 都应：
- 立即 Read `src/shared/path-utils.ts` 全文
- 复用 `projectRootsMatch` / `stableRealPath` / `normalizePath`
- **不**写 `===` / `realpathSync` / `replace(/\\/g, '/')` 重复 utility
- 看 `.peaks/standards/common/coding-style.md` 的 "Cross-platform path handling" 段

## 我 (AI) 漏改的一个文件

**`packages/peaks-loop-shared/src/version.ts` 漏改成 4.0.10** (我 Step 2 只改了 `package.json` + `shared/package.json` + `dist/version.js`)。`dist/version.js` 是 build artifact，下次 `pnpm build` 会从 source 重新生成 = 回到 4.0.9。`98bc3618` 修了 source 之后才稳。

**lesson**: version bump 改 3 个文件, **source of truth = src/version.ts, NOT dist/version.js**. 手动 Edit 改 dist 没用, 会被 build 覆盖。下次 user 或 AI bump version 必须**先**改 src, **后**跑 build, **最后** commit (or commit 一起走).
