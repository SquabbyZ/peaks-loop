# 判不了 ≠ 通过

S7 把"看着不舒服"做成可计算诊断时，试点逼出了三条规则，每一条都是先写错、再被测出来才修对的。

1. **`unmeasured` 是一等输出。** 代价型维度（对比度、状态、可访问性）在"没有任何可判输入"时会算成 `100 - 0×cost = 100`，与"判过且通过"完全同形。必须是 `judged:false, score:null`，渲染成 "not judged"。试点上 `contrast` 即如此：合同没有声明 `pairs[]`，它只能"未判定"。
2. **判据必须是项目声明的合同，不是内置常数。** `readPavedRoad()` 解析了 `tokenScale` 又丢掉，导致"以声明为准"是假的；阴影阈值写死 12px 等于发明了一个合同没有的刻度（正确做法：`unmeasured`）；字重写死 400/500/600/700 会覆盖项目声明的刻度。凡是合同没声明的，一律未测量并说明原因。
3. **检测器必须能失败。** 每个维度要有一对夹具（干净 = 0 条、已知缺陷 = 预期条）+ 一条"把规则反转后测试必须失败"的控制。S7 里 `a11y` 曾 0 条命中而真实缺陷存在（别名闭包没跟、focus 规则"全项目有一处就通过"，永远不可能失败），`states` 曾把静态配置 `.map(` 当成数据、又被 `catch (error)` 骗过。

配套的可测事实：页面作用域与值维度必须分开——路由入口算"页面"，但间距/字号/颜色要读"页面 + import 闭包"；只算入口会让 spacing 从 18,602 个值掉到 24。共享组件按导入页重复计数时，报告要给出 `distinct sites` 列，否则一个缺陷会显示成 68 条。

## How to apply

- 新增任何"评分/诊断"能力时，先问：输入为空时它会显示什么？如果不是"未判定"，就是错的。
- 每条规则先写"它看不到什么"，再把这条写进产物本身（`knownGaps`），而不是只写在文档里。
- 先跑真页再定规则：S7 的三次模型修正（页面作用域、值类闭包、评分形状）全部来自试点，没有一个能从代码里推出来。
