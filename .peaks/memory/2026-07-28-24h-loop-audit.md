# peaks-loop 24h 长任务代码审计（2026-07-28）

> **状态**：报告-only，未实施、未派 sub-agent、未改代码。
> **触发**：用户 2026-07-28 显式要求"审视 + 不改代码"。
> **scope**：`src/services/{loop,autonomous-swarm,code,context,compact,dispatch,observability}` 7 大块 + 关联 memory。

## Why

- peaks-loop 自身定位 = 24h AI 程序员编排器（user 角色 = 业务/产品审阅者，不在循环里参与技术决策）。memory `peaks-cli-24h-ai-programmer-positioning.md` 6 个硬约束（C1-C6）+ memory `peaks-loop-positioning-loop-engineering.md` 4-layer asset 模型 + 4 个 crystallization trigger。
- 24h 主路径的 4 个关键模块：`src/services/loop/run-driver.ts`（515 行主循环）/ `src/services/autonomous-swarm/autonomous-swarm-service.ts`（582 行 24h planner）/ `src/services/code/auto-compact-orchestrator.ts`（428 行 context）/ `src/services/code/batch-heartbeat-poller.ts`（sub-agent 心跳 10s 轮询 + 5min stale）。
- 现有"考虑成本"开关：context.governance 80% 硬拒、auto-compact 0.85 提前、heartbeat 5min stale gate、emit-handoff size-fear ban、`monotonic-guard` 防跑飞、dispatch record 持久化（跨 turn 续跑）。
- **audit 关键发现**（按"24h 不考虑成本"为前提）：

  1. auto-compact 的 D6.e 同步门 + 0.95 red-line 在大批 sub-agent 跑时可能让 LLM 卡几十秒；
  2. monotonic cycle 用 N 个 `cycle-<N>.json` 阻塞 fs，24h 跑 ~100 cycles 累积 100-300ms；
  3. batch-heartbeat-poller 是 in-process `setInterval`，peaks 进程退出则心跳就断（24h 离线用户场景缺守护）；
  4. auto-compact 阈值 0.85 / 0.95 在 24h 跑大批 sub-agent 时是下限，0.70 / 0.85 partial 模式可能更稳；
  5. dag-orchestrator 拓扑派发一次性 fan-out，sub-agent 规模 ≥20 容易触发 memory `peaks-code-concurrent-subagent-coordination.md` 中描述的并发冲突（2 个模式：autonomous-finish-other-rid + broken rewrite）；
  6. observability 缺 24h 专属 dashboard（当前 cycle / token / dispatch / compact 次数 / monotonic 触发数）；
  7. `src/services/context/main-session-monitor.ts` 已被 `auto-compact-orchestrator` 取代（line 62 `@deprecated`），但仍存在 → 仍有 import 风险。

## How to apply

### 7 个优化方向（按 ROI + 24h 关键度排序）

| # | 方向 | 改动面 | ROI | 24h 关键度 | 风险 |
|---|---|---|---|---|---|
| **A** | context-spillover to disk（D6.e 替代）：in-flight batch 期间把 turn 上下文 spill 到 `<sid>/spill/<turnId>.json`，LLM 进入"无 context" 模式（仅读 spill），sub-agent 完成后再 hydrate | 新增 `src/services/context/spillover-store.ts` + `auto-compact-orchestrator` 接入 | 高 | 极高 | **大**（影响 LLM turn 边界语义，需完整 design slice） |
| **B** | heartbeat 拆独立守护命令：`peaks heartbeat watch <batch-id>` 独立可外部化运行（`nohup peaks heartbeat watch ... &`） | 新增 CLI 命令 + `batch-heartbeat-poller` 切可外部化 | 中高 | 高 | 中（模块化已就位，注入 `now` / `readRecords`） |
| **C** | auto-compact 阈值分模式（24h 模式 0.70 / 0.85 partial） | `auto-compact-orchestrator` 接受 mode 参数 + partial compact | 中 | 高 | 中（涉及 v2.13.0 zero-pause contract，必须先 lint prose 红线） |
| **D** | monotonic cycle 用 jsonl-store 替代 N-file | 改 `run-driver.ts` 持久化层（已有 `observability/jsonl-store.ts` 可复用） | 低 | 中 | 极低 |
| **E** | DAG wave 化 + barrier（每 wave ≤ 6 并发 + artifact-pass） | 改 `dag-orchestrator.ts` | 中高 | 中（sub-agent ≥20 才显著） | 中 |
| **F** | 24h dashboard 指标（cycle / token / dispatch / compact / monotonic 次数） | 扩 `dashboard/` + `observability/` | 低 | 中（用户感知） | 低 |
| **G** | main-session-monitor 硬拒 import（非 @deprecated 路径） | 加 `tests/unit/standards/main-session-monitor-ban.test.ts` + PreToolUse hook 阻断 | 极低 | 低 | 极低 |

### 立即建议

- **第一刀**：B（24h 离线场景）+ G（成本极低，5 分钟 + 1 vitest case），把 24h 离线用户场景的"无 LLM 守护"先补上。
- **第二刀**：D（成本 30 分钟 + 1 vitest case，几乎无风险）。
- **第三刀**：A（需要完整 design slice + RD 派发，留给 4.1 / 4.2）。
- **不在 4.0.0 GA 路径上做**：E / F（涉及面广，至少 1 天工作量）。
- **注意**：C 涉及 v2.13.0 zero-pause contract 修改，**必须先 `peaks audit red-lines` lint prose**，避免引入 "ask the user to compact" 之类的反模式字符串。
