**一个组件若把"自己派生的值"写进某处、又在后续运行里把该值读回来当作自己的输入，它就把自己锁在了首次猜测上。**

2026-09-13 实测（peaks-loop 方案 A1，QA 在副本复现）：peaks-loop 把解析出的上下文窗口写进 harness 键，又把该键读回当作自己的窗口，并对该层**禁用了"观测值超出窗口时上修"的救援机制**。结果：

| 步骤 | 实测 |
|---|---|
| 新会话 30K token → 写入 200000 | 200000 |
| **同一会话涨到 500K token** | **仍是 200000，ratio 饱和在 1.0** |
| **删掉该键作对照** | **1000000**（正确） |

即：**被禁用修正的那一层，恰好就是唯一会出错的那一层。** 用户最初卡死的形状就是"启发式没认出模型 → 误判为 200K"；A1 把它从"一次性误判"变成"永久按 200K 算"。

**Why:** 写入值是*写入那一刻*的解析结果，而"读回"使它看起来像用户意图 —— 于是纠错机制不再适用。这不是 bug 的实现方式，是**结构本身**。

**How to apply:** 设计任何"自我配置"回路时问三件事 ——
1. **读回来的值，能否与"用户显式设置的值"区分开？**（不能区分 → 你的产物会被当成用户意图）
2. **那条路径上的纠错机制还在吗？**（写回 + 读回常常顺手把纠错关掉了）
3. **若两者冲突（既要打破自锁、又要保持单一事实来源），代价是什么？** —— 这个冲突必须被**明说**，不能悄悄只满足一边。
